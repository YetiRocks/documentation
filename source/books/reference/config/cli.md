## Usage

```bash
yeti [COMMAND] [OPTIONS]
```

With no command: install wizard (first run) or status screen (already installed).

## Commands

| Command | Description |
|---------|-------------|
| `start [N]` | Start 1 standalone instance (default); `start N` (2..9) brings up an N-node loopback cluster (dev) |
| `up [--watch DIR]` | Start the server (alias of start); --watch hot-reloads changed apps |
| `stop` | Stop background instance |
| `restart` | Restart (stop + start) |
| `install` | Run setup wizard (first-time or re-install) |
| `update` | Update to latest version |
| `logs` | Tail the server log |
| `status` | Pretty-printed health + app summary |
| `doctor` | Diagnose the install + app-build toolchain (per-check report) |
| `new <NAME>` | Scaffold a new application (templates: basic|mcp|oidc|ai|edge-go|edge-py|edge-js) |
| `deploy` | Package and deploy an application to a server |
| `undeploy --name <DEP>` | Take a deployment off the fleet (--deactivate keeps its revisions so it can come back) |
| `clone --leader <SEED>` | Bootstrap a fresh replica: pull + materialize the artifact, join + catch up |
| `compose` | Compose multiple local apps into one deployment (localhost/<name>) |
| `sign <WASM>` | Sign a wasm component via cosign |
| `verify [WASM]` | Check installation integrity; with <WASM>, verify cosign signature |
| `config lint` | Lint a yeti-config.yaml against a deployment profile |
| `schema lint` | Lint customer GraphQL schemas for anti-patterns (gates CI) |
| `registry push/pull` | Push/pull components as digest-addressed, cosign-signable OCI artifacts |
| `acceptance --mode M` | Run the acceptance conformance matrix (dev); Uncovered = RED, one pass/fail/waived report |
| `help [TOPIC]` | Print help (top-level or per-subcommand) |

## Options

| Option | Description |
|--------|-------------|
| `-f, --foreground` | Run in foreground (default: background) |
| `-V, --version` | Print version |
| `-h, --help` | Print help |
| `--buildonly` | Compile applications only, then exit |
| `--apps <a,b,c>` | Only load specified applications |
| `--watch <DIR>` | up: hot-reload changed apps under <DIR> (needs -f) |
| `--port <PORT>` | HTTP port (default: 9996) |
| `--dir <PATH>` | Root directory (default: ~/yeti) |
| `start [N] (1..9)` | Instances to start (default 1). 1 = a standalone node; 2..9 = an N-node loopback cluster (dev builds only) |
| `--require-ref <REF>` | Refuse to start unless this binary IS the build under test: built from <REF> (e.g. origin/dev), with the promotion candidate's features, in the release profile. Names every difference on refusal. Also $YETI_REQUIRE_REF; `yeti verify --require-ref <REF>` checks without starting anything. |
| `--require-features <a,b,c>` | With --require-ref: the features the binary must carry (default: yeti-cli's `default` set — a fleet artifact lacks `dev`, so it cannot run --cluster N). `any` drops the check. Also $YETI_REQUIRE_FEATURES. |
| `--require-profile <NAME>` | With --require-ref: the cargo profile the binary must have been built with (default: release). `any` drops the check. Also $YETI_REQUIRE_PROFILE. |
| `--root-app <ID>` | start/up: the app served at origin `/` (others at /{app}/). App-id or folder name (folder `yeti-www` → id `www`). |
| `--bundle <a b c>` | start/up/bundle: compose only these apps into the deployment (app-ids or folder names) |
| `--save <NAME>.json` | start/up/bundle: persist the resolved deployment as a named manifest under deployments.root. Without it the local default deployment is EPHEMERAL — no default.json is written, so it never drifts and never collides with Fabric's hash routing. Pin a saved one via `deployments.default`. |
| `--deployment <NAME>` | start/up: serve an existing saved manifest verbatim |

## New Options

| Option | Description |
|--------|-------------|
| `--template=<NAME>` | Template: basic | mcp | oidc | ai (default: basic) |
| `--account-id=<ID>` | Account id stamped into Cargo.toml (default: yeti) |
| `--rootdir=<PATH>` | Override rootDirectory (default: from settings.toml) |

## Deploy Options

| Option | Description |
|--------|-------------|
| `--dir <PATH>` | Application directory to deploy (default: .) |
| `--name <HASH>` | deployment_hash to publish under (default: app id) |
| `--dry-run` | Compile + assemble bundle only; don't deploy |
| `--deactivate` | On `undeploy`: stop serving fleet-wide but KEEP every revision (reversible) |
| `--wasm <PATH>` | Register a PREBUILT .wasm component (no build): validate it for this host, content-address it, and tag a registry entry (--name / --deploy-version) composable into a deployment. |
| `--deploy-version <V>` | Registry version handle for the --wasm upload (default: 0.1.0) |
| `validate` | Dev/deploy parity preflight: compose every app, boot deployment mode on a scratch socket, smoke-test each, tear down. Honors --apps. Exits nonzero naming any failing app. |

## Install Options

| Option | Description |
|--------|-------------|
| `--admin-user <USER>` | Admin username (default: YETI_ADMIN) |
| `--admin-password <PW>` | Admin password (required for headless) |
| `--agree-to-terms` | Accept terms of use (required for headless) |

## Environment Variables

| Variable | Description |
|----------|-------------|
| `YETI_HOME` | Override settings directory (default: ~/.yeti) |
| `APPLICATION_PORT` | Override HTTP port |
| `LOG_LEVEL` | Override log level (default: info) |
| `YETI_REQUIRE_REF` | Git ref this binary must have been built from; start refuses otherwise (= --require-ref). Inherited by spawned nodes. |
| `YETI_REQUIRE_FEATURES` | Features the binary must carry when a ref is pinned (= --require-features); `any` drops the check. Inherited by spawned nodes. |
| `YETI_REQUIRE_PROFILE` | Cargo profile the binary must have been built with when a ref is pinned (= --require-profile); `any` drops the check. Inherited by spawned nodes. |

Running 'yeti' with no command will install (if needed) then start.
Provide --admin-password and --agree-to-terms to skip the interactive wizard.
